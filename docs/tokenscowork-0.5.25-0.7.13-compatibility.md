# TokensCowork 0.5.25 / 0.7.13 / 0.7.18 适配（0.3.14）

目标宿主：

- TokensCowork 0.5.25，DSH 0.1.5-rc.2；
- TokensCowork 0.7.13 / 0.7.18，DSH 0.2.1-rc.2，Cordis 4.0.5。

## 改动

- 保留 TokensCowork 0.5.25 使用的 DSH 0.1.5-rc.2 兼容范围，增加 TokensCowork 0.7.13 使用的精确版本 0.2.1-rc.2；通过 engines.dsh 和 peerDependencies 声明。不使用版本豁免。
- 开发依赖固定到新版宿主 SDK；更新 pnpm 锁文件。
- 图片结果在 TokensCowork 0.7.13 按槽位传入的 sessionId 读取附件，避免依赖新版已移除的全局 current 字段；TokensCowork 0.5.25 继续使用旧宿主的全局 current 回退路径。
- 客户端通过两条运行时都支持的 locale 注册/槽位注入接口提供中英文文案；界面跟随 TokensCowork 当前语言重新渲染，Host 问题 ID、选项值和生成参数保持不变。
- TokensAPI 上传响应若带冗余 Host，只在它与 upload_url 主机完全一致时接受，并且不把它作为可覆盖的请求头发给对象存储。
- 媒体问答卡片同时支持旧版 `cancel()` 和新版 `dismiss()` 载体。新版右上角 X 通过明确的取消答案中断向导，不把仅隐藏面板当作取消，也不触发生成。
- 默认选项由媒体专用问题 ID 携带，即使宿主移除 `initialSelected` 仍能恢复高亮。单选点击后直接下一步，最后一项完成后直接生成，不再增加参数复核页。
- Host 输出规范的模型显示名，并把答案还原为 API ID；图片生成默认 H3 Image，编辑默认 Qwen Image，视频默认 MiniMax H3。旧 Image 2、LTX 2.3 和 Seedance 不再作为生成选项，旧默认值只在内存中迁移。
- H3 Image 已确认的分辨率等可选参数若被最终工具调用漏传，仅从当前会话、当前用户请求和相同意图的有效确认记录中恢复。显式冲突、取消、过期和跨请求参数仍会被拒绝。
- 图片、图片编辑和视频在聊天中显示生成状态和内联结果。S3 视频通过 Host 的 TLS 1.2 路由按 Range / HEAD 流式播放，重试播放不重提生成任务。

## 验证

- 新 SDK 类型检查和构建。
- 自动化用例覆盖问答确认、取消、图片上传、生成请求、视频参数、网络恢复、新旧宿主的会话附件选择、旧模型迁移和当前请求已确认参数恢复。
- 独立浏览器使用已安装 TokensCowork 0.7.18 的 React/Cordis、真实 `PendingQuestion` 和 `SlotCore`，与原生通用问答卡片同时注册，验证媒体卡片能正常接管。
- 浏览器验证中英文图片生成、图片编辑和视频参数的默认高亮、单击前进、新版 X 取消、旧版取消、聊天生成状态、MP4 播放及重试、图片放大和独立下载。

兼容性检查通过时不传任何版本豁免。

本轮自动化检查为隔离验证，不读取用户凭证，不提交真实付费生成任务，也不重启桌面应用。本地 0.7.18 已安装 0.3.14 并经用户验收；发布前继续核对产物一致性。TokensCowork 0.5.25 / 0.7.13 的验证使用历史验收基线和新旧接口回归，本轮未重新安装或启动这两个旧版桌面应用，不声称对其完成了新的端到端实测。
